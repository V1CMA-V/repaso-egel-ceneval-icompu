## ¿Qué es?

<Callout type="que">
La **notación Big-O** describe cómo **crece el tiempo (o la memoria)** de un algoritmo cuando el tamaño de la entrada $n$ crece; interesa el **peor caso** y el **orden de magnitud**, no los segundos exactos.

Orden de menor a mayor crecimiento:

$$O(1) < O(\log n) < O(n) < O(n \log n) < O(n^2) < O(2^n) < O(n!)$$
</Callout>

## Cómo calcular la complejidad de un código

1. **Ignora constantes y términos menores**: $3n^2 + 5n + 7 \to O(n^2)$.
2. Una **instrucción simple** → $O(1)$.
3. Un **ciclo** que recorre $n$ elementos → $O(n)$.
4. **Ciclos anidados** → se **multiplican**: dos ciclos de $n$ → $O(n^2)$.
5. Ciclos **secuenciales** → se **suman**, y domina el mayor: $O(n) + O(n^2) = O(n^2)$.
6. Un ciclo que **divide o multiplica el contador por 2** en cada vuelta → $O(\log n)$.

```
// O(n^2): ciclos anidados
for i in 1..n
  for j in 1..n
    hacer_algo()

// O(log n): el contador se duplica
i = 1
while i < n
  i = i * 2

// O(n^2): el ciclo interno depende de i (1 + 2 + ... + n = n(n+1)/2)
for i in 1..n
  for j in 1..i
    hacer_algo()
```

<Callout type="tip">
Pregúntate: **"¿cuántas veces se ejecuta la instrucción más interna?"** Si el contador **se parte o se duplica**, es **logarítmico**; si hay **dos recorridos anidados completos**, **cuadrático**.
</Callout>

## Algoritmos de ordenamiento

| Algoritmo | Mejor | Promedio | Peor | ¿Estable? | Notas |
| --- | --- | --- | --- | --- | --- |
| **Burbuja** | O(n) | O(n²) | O(n²) | **Sí** | Simple y lento |
| **Selección** | O(n²) | O(n²) | O(n²) | No | **Pocos intercambios** |
| **Inserción** | O(n) | O(n²) | O(n²) | **Sí** | **Muy buena con datos casi ordenados** y listas pequeñas |
| **Merge sort** | O(n log n) | O(n log n) | **O(n log n)** | **Sí** | **Divide y vencerás**; usa **memoria extra O(n)** |
| **Quicksort** | O(n log n) | O(n log n) | **O(n²)** | No | **Pivote**; **en sitio**; el más rápido en la práctica |
| **Heapsort** | O(n log n) | O(n log n) | O(n log n) | No | Usa un **heap**; en sitio |

- Un ordenamiento es **estable** si **conserva el orden relativo** de los elementos con la misma clave (importante al ordenar por varios criterios).
- **Merge sort**: garantiza $O(n \log n)$ y es **estable**, pero necesita memoria auxiliar. **Quicksort**: **peor caso $O(n^2)$** (ej. pivote malo con datos ya ordenados).

<Callout type="tip">
"**Estable y garantizado** $O(n \log n)$" → **merge sort**. "**Datos casi ordenados**" → **inserción**. "**Sin memoria extra y rápido en promedio**" → **quicksort** (o heapsort si se necesita garantía).
</Callout>

## Búsqueda

- **Lineal**: recorre uno por uno. $O(n)$. Sirve con datos **sin ordenar**.
- **Binaria**: compara con el elemento **central** y descarta la mitad. $O(\log n)$. **Exige datos ordenados** (y acceso aleatorio). Para **1 millón** de elementos, ≈ **20 comparaciones** ($2^{20} \approx 10^6$).
- **Tabla hash**: $O(1)$ promedio.

## Importante recordar

<Callout type="importante">
- **Ciclos anidados = O(n²)**; contador que se **duplica/parte** = **O(log n)**.
- **Búsqueda binaria**: **solo con datos ordenados**; $O(\log n)$.
- **Quicksort**: peor caso **O(n²)**, no estable. **Merge sort**: **O(n log n)** siempre, estable, memoria extra.
- **Burbuja e inserción** son estables; **selección y quicksort** no.
- Fibonacci recursivo ingenuo: $O(2^n)$.
</Callout>

## Errores comunes

<Callout type="error">
- Aplicar **búsqueda binaria en un arreglo sin ordenar**.
- Decir que **quicksort** es $O(n \log n)$ **siempre**.
- Incluir las **constantes** en Big-O ($O(2n)$ es simplemente $O(n)$).
- Confundir el **mejor caso** (burbuja $O(n)$ con optimización) con el **peor caso**.
</Callout>

## Ejemplo resuelto

> ¿Cuántas comparaciones, como máximo, necesita una búsqueda binaria en un arreglo ordenado de 1 024 elementos?

$\log_2 1024 = 10$, así que **10 comparaciones** (≈ 11 contando la última). Una búsqueda lineal necesitaría hasta **1 024**.
